# StoryHeaven 인과 품질·대량 보완 운영 계획 v4

작성일: 2026-09-19  
선행 설계: `serial-quality-v3-plan.md`

## 운영 데이터 진단

2026-09-19 공개 전 보류 원고 19건을 분석했다.

- 19건 전부 `causality` 기준 미달
- 12건은 `canonConsistency`도 함께 미달
- 대부분 독자 체감 점수는 90점 이상이어서 작품 전체가 무너진 경우가 아니라, 장면 안의 짧은 인과 연결이 빠진 경우였다.
- 반복 유형은 능력 대상 자격, 문서의 생성·소유·이동, 계약·권한의 근거, 지급 결과, 도구·운송수단의 사전 준비, 음식 안전 확인, 행동과 결과 사이의 물리적 연결이었다.
- 기존 재보완은 최신 지적만 전달하고 과거 수정 사항을 합격 조건으로 보존하지 않았다. 운영자 재보완 뒤 자동 수정 횟수도 다시 부여하지 않아 한 번 실패하면 곧바로 운영자 목록으로 돌아왔다.

## 목표

1. 장면을 쓰기 전에 인과 누락을 예방한다.
2. 한 번 고친 지적이 다음 재작성에서 되돌아가지 않게 한다.
3. 운영자가 한 번 보완을 요청하면 제한된 자동 보완·재검수를 끝까지 수행한다.
4. 다수 원고를 한 번의 선택 작업으로 대기열에 넣는다.
5. 클릭 직후 접수 상태를 보여 서버 이상으로 오해하지 않게 한다.

## 구현 단계

### A. 장면별 인과 체크포인트

- **구현:** 신규·재설계 회차 카드에 장면마다 `causalCheckpoints`를 저장한다.
- **필드:** 결과, 사전 근거, 근거 위치, 행위자, 행동, 직접 결과, 남은 결과, 금지 편법.
- **범위:** 능력뿐 아니라 문서, 계약, 권한, 단서, 지급, 음식 안전, 도구, 운송, 구조 자원과 물리적 해결을 포함한다.
- **검증:** 모든 장면에 정확히 하나의 체크포인트가 없으면 카드 계약을 거부한다.

### B. 누적 수정 의무

- **구현:** 운영자 보완 시 치명적 지적을 `repairLedger`에 안정 키로 누적한다.
- **집필 검증:** 재작성 결과는 각 키마다 실제 최종 원고에 존재하는 해결 문장을 `repairEvidence`로 제출한다.
- **편집 검증:** 최종 검수는 모든 키를 `resolved` 또는 `unresolved`로 재판정하며, 미해결 항목이 있으면 승인할 수 없다.
- **회귀 방지:** 새 지적이 생겨도 이전 해결 문장을 계속 합격 조건으로 유지한다.

### C. 제한된 자동 복구

- **구현:** 운영자 보완 요청 시 자동 원고 보완 횟수를 새로 시작한다.
- **구현:** 일반 자동 제작은 회차 구성 보정 1회 제한을 유지한다.
- **구현:** 운영자가 재보완을 요청한 원고는 인과·설정 실패가 남을 때 회차 구성 보정을 1회 더 허용한다.
- **안전장치:** 운영자 요청 회차당 최대 2회 구성 보정이며 무한 반복하지 않는다.

### D. 운영 화면과 일괄 접수

- **구현:** `프롤로그 등록 전 확인`에 개별 체크박스, 전체 선택, 선택 건수, 선택 원고 일괄 보완 버튼을 추가한다.
- **구현:** 한 번의 관리자 API 요청으로 최대 50건을 접수하고 서버는 동시 3건까지만 안전하게 준비한다.
- **구현:** 개별·일괄 버튼은 클릭 즉시 접수 중 상태를 표시하고 실제 원고 처리는 백그라운드 대기열에서 순서대로 진행한다.

### E. 운영 검증

- 현재 보류 원고를 새 보완 방식으로 다시 접수한다.
- 아래 지표를 다음 운영 점검에서 비교한다.
  - 재보완 1회 뒤 공개 준비 전환율
  - 같은 `repairLedger` 키의 재발률
  - 새 치명적 지적 발생률
  - 원고당 추가 구성 보정·재작성 횟수
  - 버튼 클릭부터 접수 피드백까지의 체감 시간

## 완료 기준

- 운영자 한 번의 보완 요청 뒤 같은 지적이 해결되지 않은 채 즉시 다시 목록으로 돌아오지 않는다.
- 이전 지적을 해결한 문장이 후속 재작성에서 사라지면 계약 또는 최종 검수가 이를 차단한다.
- 여러 작품을 한 번에 선택해 접수할 수 있다.
- 실제 치명적 결함만 제한된 자동 보완 뒤 운영자에게 돌아온다.
