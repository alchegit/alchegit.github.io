# StoryHeaven 장르·문체·서사 품질 개선 설계 v3

- 작성일: 2026-08-30
- 대상: 이 설계가 배포된 뒤 새로 등록하는 자동연재 설정과 새 작품
- 제외: 기존 공개 원고의 자동 개작, 특정 작품·작가의 문체 모사, 작품 원문을 학습 자료나 프롬프트에 넣는 작업
- 선행 설계: `serial-quality-v2-plan.md`의 후보 경쟁, 장기 기억, 다중 비평, 3편 파일럿 구조를 유지한다.

## 목표

2026-09-07 후속 설계: [작품 방향별 재미와 유머](serial-direction-plan.md). 웃음은 작품 방향에 따라 선택적으로 적용하며, 진중한 서사와 처절한 성장·복수는 웃음 없이 성장·긴장·카타르시스로 평가한다. 이 원칙이 아래 문체의 유머 권고보다 우선한다.

현재 시스템의 결함 방지 능력 위에 독자가 실제로 오래 읽을 이유를 더한다. 운영자가 복잡한 태그를 조립하지 않아도 장편 판타지의 핵심 재미가 분명한 장르 계열 하나와 일관된 문체 하나를 선택할 수 있어야 한다. 새 작품은 장르의 익숙한 즐거움, 인물의 고유한 선택, 누적되는 관계, 납득되는 인과, 자연스러운 한국어 문장을 동시에 갖춰야 한다.

목표는 참고 작품과 비슷한 문장이나 설정을 만드는 것이 아니다. 작품명은 조사와 설계 문서에서만 장르를 이해하는 참고 표지로 사용하고, 실제 AI 작업에는 작품명·작가명·원문·고유 설정을 전달하지 않는다. 여러 작품에서 공통으로 관찰되는 고수준 제작 원리만 서버가 관리하는 독립적인 장르·문체 계약으로 바꾼다.

## 현재 구조 감사

### 이미 있는 기반

- 기본 장르 9종과 장르별 세부장르, 최대 3개 기본 장르 조합
- 전개 속도·긴장·호기심·반전·감정·관계·액션·묘사·웃음·참신성 조절
- 작품별 `voiceProfile`에 서술 거리, 문장 리듬, 대화 비율, 유머 방식, 묘사 밀도, 감정 표현을 저장하는 구조
- 서로 다른 4개 기획 후보와 편집 모델의 자동 선정
- 프롤로그와 본편 1·2화의 3편 파일럿, 독립 비평과 자동 승격 관문
- 장기 기억, 관계망, 세계 동역학, 아크 종료 재기획

### 확인된 부족한 점

1. **기본 장르가 취향과 어긋난다.** 운영 화면은 `판타지 > 현대판타지`로 시작한다. 정통 모험, 신화적 세계, 무협 융합, 게임 성장 계열을 원할 때마다 운영자가 조합을 알아서 만들어야 한다.
2. **장르 태그가 독자 경험 묶음이 아니다.** `정통판타지`나 `게임·시스템` 한 항목만으로는 주인공의 성장 방식, 아크 보상, 동료 역할, 세계 압력과 전투·탐험·생활 리듬이 확정되지 않는다.
3. **문체와 창작 강도가 섞여 있다.** 현재 웃음 수치는 웃음 빈도만 조절하고, `가볍고 유쾌한 목소리`와 `진지하고 웅장한 목소리`를 구분해 저장하지 않는다.
4. **문체 카드가 모델 생성값이다.** 설정집 단계에서 AI가 `voiceProfile`을 만들기 때문에 운영자의 취향이 강제되지 않으며 작품마다 우연히 달라질 수 있다.
5. **문체 전용 합격 관문이 없다.** 한국어 가독성과 장면 표현 검수는 있지만 문체 적합도, 대화 인물성, 어조 일관성, 문장 리듬을 독립적으로 판정하지 않는다.
6. **규칙이 많아도 재미를 보장하지 못한다.** 첫 문단 정보량, 장면 수, 점수 기준이 결함은 줄이지만 인물의 존재감, 기대한 장르 쾌감, 웃음과 비애의 대비, 기억에 남는 선택을 대신할 수 없다.
7. **검수 입력이 지나치게 크다.** 같은 큰 설정 묶음이 여러 독립 비평에 반복되어 비용과 시간이 늘고, 각 비평이 자기 역할보다 전체 체크리스트를 의식하기 쉽다.
8. **품질 개선을 비교할 기준선이 부족하다.** 새 규칙을 추가해도 기존 방식보다 실제로 나아졌는지 동일 조건의 비공개 파일럿으로 비교하는 운영 절차가 없다.

## 장르 계열 설계

### 1. 정통 영웅 모험

- 기본 조합: `판타지 > 정통판타지` + `액션·모험 > 히어로 또는 탐험·유적`
- 핵심 독자 약속: 인물이 위험한 세계를 이동하며 임무·동료·강적을 만나고, 선택의 대가로 영웅의 자격과 책임이 달라진다.
- 반복 보상: 탐험, 전투, 발견, 동료 합류, 명예와 책임의 변화
- 금지: 힘의 등급만 올라가는 전투 목록, 이유 없이 주인공을 숭배하는 조연, 매 아크 더 큰 신만 추가하는 확대

### 2. 신화적 세계 대서사

- 기본 조합: `판타지 > 신화·독자세계` + `시대·역사 > 시대판타지 또는 전쟁`
- 신규 세부장르: 판타지에 `신화·독자세계`를 추가한다.
- 핵심 독자 약속: 서로 다른 문화·종족·세력이 자기 논리로 움직이고, 개인의 선택이 세계 질서와 주제 질문을 구체적인 결과로 바꾼다.
- 반복 보상: 낯선 문화의 발견, 가치 충돌, 정치적 선택, 경이, 역사적 결과
- 금지: 고유명사와 연대기 나열, 철학을 말하는 인물만 있고 현재 목표가 없는 장면, 신비하다는 이유로 인과를 생략하는 전개

### 3. 무협 융합 판타지

- 기본 조합: `판타지 > 동양판타지` + `액션·모험 > 무협`
- 핵심 독자 약속: 수련과 대결로 실력이 축적되며 은원·문파·신념·책임이 강함의 사용 방향을 압박한다.
- 반복 보상: 수련 성과, 기술의 응용, 강적과의 수 싸움, 은원 회수, 세력 질서 변화
- 금지: 경지 이름만 바뀌는 수치 상승, 모든 갈등을 압도적 힘으로 끝내기, 무협과 서양 판타지를 인과 없이 장식처럼 병치하기

### 4. 게임 모험 성장

- 기본 조합: `판타지 > 게임·시스템` + `액션·모험 > 탐험·유적`
- 선택 변형: 장인 성장에는 `드라마 > 요리·장인`, 대규모 세력 성장에는 `판타지 > 영지경영`을 한 축만 추가한다.
- 핵심 독자 약속: 분명한 목표와 규칙 아래 작은 성취가 능력·관계·지위·선택지를 누적해서 바꾼다.
- 반복 보상: 퀘스트 해결, 희귀 발견, 기술 숙련, 제작·거래, 동료 협력, 세력 확장
- 금지: 상태창 자체가 장면을 대신하는 전개, 보상 수치만 있고 사용 결과가 없는 성장, 우연한 히든 보상의 연속

### 신규 기본값

- 운영 화면의 새 기본값은 `장편 판타지 추천 랜덤`으로 둔다.
- 서버는 위 네 계열 중 하나를 일정 등록 시 한 번만 고르고 실제 장르·세부장르와 `genrePresetId`를 저장한다.
- 작품마다 다시 뽑지 않으며 설정집, 아크, 회차와 검수에서 같은 계열을 유지한다.
- 운영자는 네 계열 중 하나를 직접 선택하거나 기존의 모든 장르 수동 설정과 완전 랜덤을 사용할 수 있다.
- 초기 가중치는 정통 영웅 모험 30%, 신화적 세계 대서사 15%, 무협 융합 20%, 게임 모험 성장 35%로 시작하고 실제 파일럿 통과율과 운영자 평가 뒤 조정한다.

## 문체 계열 설계

문체는 장르와 독립된 `proseStylePreset`으로 저장한다. 작품명이나 작가명을 프리셋 이름과 프롬프트에 사용하지 않는다. `랜덤`은 작품 기획 전에 한 번만 확정하며 후속 회차에서 바뀌지 않는다.

### 1. 가볍고 유쾌한 몰입형 - 신규 기본값

- 시점: 주인공 판단에 가까운 제한적 3인칭 또는 자연스러운 1인칭
- 문장: 짧고 명확한 행동문을 기본으로 하되 감정의 결과에는 한 호흡의 여유를 준다.
- 어휘: 중학생도 문맥에서 바로 이해할 생활어 중심
- 유머: 농담을 붙이지 않고 욕망, 허점, 체면, 관계의 엇갈림에서 발생
- 대화: 정보 전달보다 협상·회피·견제·친밀감 변화가 먼저 보이게 함
- 금지: 매 문단 드립, 진지한 손실을 즉시 농담으로 무효화, 인터넷 유행어 남용, 가벼움과 무책임의 혼동

### 2. 진지하고 웅장한 서사형

- 시점: 인물에 밀착하되 역사와 세계의 무게를 선택의 결과에서 넓혀 보여주는 제한적 3인칭
- 문장: 평상시에는 절제하고 결정·전투·상실의 핵심 순간에만 리듬과 문장 길이를 확장
- 어휘: 정확한 보통말을 중심으로 하며 한자어·고어는 시대와 인물에 필요할 때만 사용
- 유머: 긴장을 무너뜨리지 않는 건조한 반응이나 관계의 숨구멍 정도
- 묘사: 추상적인 장엄함보다 규모, 거리, 소리, 군중, 물자의 변화로 웅장함을 증명
- 금지: 모든 문장을 비장하게 쓰기, 뜻이 흐린 수사, 선언과 철학 대사 남발, 과도한 감탄과 운명론

### 3. 담백하고 선명한 모험형

- 시점: 행동과 선택을 빠르게 읽을 수 있는 제한적 3인칭
- 문장: 원인-행동-결과가 선명하고 장면 전환이 빠르며 핵심 이미지 하나만 남김
- 유머: 인물 성격이 드러나는 짧은 반응
- 강점: 정통 모험, 무협, 전투·추적 중심 회차의 가독성
- 금지: 보고서 문장, 동작 목록, 감정 없는 속도전

### 4. 어둡고 긴장감 있는 몰입형

- 시점: 불확실한 정보와 신체 감각에 가까운 제한적 서술
- 문장: 짧은 압박과 긴 관찰을 교차하되 독자가 공간과 원인을 잃지 않게 함
- 유머: 인물의 방어 기제로만 제한적으로 사용
- 금지: 모호한 어둠·피 냄새·심장 박동의 반복, 잔혹함을 깊이로 착각, 사실을 숨겨 만든 가짜 반전

### 문체와 창작 강도의 관계

- `proseStylePreset`은 문장의 목소리와 정보 배열을 정한다.
- 기존 `creativeControls.humor`는 웃음 보상의 빈도와 크기만 조절한다.
- 기존 `pace`, `description`, `emotion`은 문체 계열 안에서 허용 범위를 미세 조정한다.
- 예: 진지하고 웅장한 문체에 웃음 3을 선택할 수 있지만, 유머는 장면을 멈추는 개그가 아니라 인물 관계의 숨구멍으로 구현한다.

## 데이터 계약

첫 구현은 Oracle 컬럼을 늘리지 않고 `storyheaven_serial_schedules.concept_policy_json` 안에 다음 값을 저장한다.

```json
{
  "genrePreset": {
    "requestedId": "curated-long-fantasy-random",
    "resolvedId": "game-progression-adventure-v1",
    "version": "2026-08-30"
  },
  "proseStyle": {
    "requestedId": "light-witty",
    "resolvedId": "light-witty-v1",
    "version": "2026-08-30"
  }
}
```

서버가 요청값을 검증하고 랜덤을 해소한다. 작업자는 자유 텍스트 대신 서버가 붙인 읽기 전용 프로필을 받는다. 설정집의 `voiceProfile`은 프로필을 새로 발명하지 않고 다음 두 층으로 나눈다.

- `lockedStyle`: 서버 프리셋에서 복사한 서술 거리 범위, 문장 리듬, 어휘 수준, 대화 비율 범위, 유머 원천, 묘사 원칙, 금지 습관
- `storySpecificVoice`: 선택한 작품 안에서만 쓸 감각 팔레트, 인물별 말의 정보 순서, 대표 이미지와 반복 금지 표현

서버는 `lockedStyle`이 일정의 확정 프로필과 다르면 설정집을 거부한다. 이후 회차 카드, 초고, 재작성과 편집 검수에는 같은 프로필 ID와 해시를 전달한다.

## 제작 파이프라인 개선

### 단계 A. 장르 약속이 다른 후보 생성

- 네 기획 후보는 선택된 장르 계열의 핵심 약속을 모두 지키되 주인공 욕망, 관계축, 세계 압력, 반복 동력과 대표 장면이 달라야 한다.
- 후보마다 `genreExperiencePlan`을 추가한다: 장기 독자 판타지, 1권의 성장 축, 반복 보상 4개, 아크 변주 4개, 힘의 한계, 휴식 회차의 재미, 실패 시 진부해질 위험.
- 게임 성장 후보는 수치가 아니라 성취가 생활·관계·지위에 미치는 결과를, 무협 후보는 경지보다 선택과 은원의 대가를, 대서사 후보는 고유명사보다 세력의 목적과 사회적 결과를 우선한다.

### 단계 B. 문체 자동 오디션

- 선정된 기획으로 600~900자의 비공개 원문 샘플을 한 번 만든다.
- 샘플은 실제 프롤로그에 복사하지 않으며, 같은 인물의 작은 목표·대화·행동·결과를 보여주는 독립 장면으로 만든다.
- 편집 모델은 문체 적합도, 자연스러운 한국어, 인물 목소리, 설명 밀도와 읽는 즐거움을 평가한다.
- 실패하면 전체 기획을 버리지 않고 문체 카드만 한 번 보정한다. 이 과정은 작품당 최초 한 번만 실행한다.

### 단계 C. 장편 핵심축과 설정집

- 세계의 규모보다 주인공의 장기 욕망, 중심 관계, 첫 권의 구체적 손실과 성취를 먼저 확정한다.
- 세계 규칙은 `누가 무엇을 원하고 어떤 자원과 제약으로 움직이며 어떤 2차 결과를 만드는가`까지 연결한다.
- 능력·무공·게임 규칙은 핵심 효과, 숙련 경로, 대가, 우회 가능성, 사회적 가치와 악용 가능성을 기록한다.
- 먼 10권 계획은 현재처럼 1권 상세, 2~3권 방향, 이후 가설로 유지한다.

### 단계 D. 회차 재미 설계

회차 카드에 다음 값을 추가한다.

- `genrePayoff`: 이번 화에 실제로 끝까지 보여줄 장르 보상
- `characterDelight`: 주인공 또는 조연의 매력적인 판단·허점·능숙함이 드러나는 순간
- `causalChain`: 원인 → 선택 가능성 → 선택 → 즉시 결과 → 뒤늦은 결과
- `toneMovement`: 가벼움·긴장·경이·비애 중 시작과 끝의 온도 변화
- `dialogueConflict`: 대화에 참여하는 각 인물의 서로 다른 목적과 대화 뒤 달라지는 관계
- `earnedProgress`: 수치가 아니라 인물의 선택지가 넓어지거나 좁아진 구체적 변화

모든 항목을 매 장면에 강제하지 않는다. 회차 전체에 하나의 중심 보상과 온도 변화가 선명하면 통과한다. 체크리스트를 본문 순서로 그대로 출력하는 양식화를 금지한다.

### 단계 E. 집필과 국소 보정

- 집필 모델에는 서버가 만든 1페이지 분량의 `writingBrief`만 우선 제공한다. 전체 설정은 충돌 확인이 필요한 구조화 데이터로 분리한다.
- `writingBrief`에는 이번 회차 목표, 인물별 목적, 인과 사슬, 장르 보상, 문체 프로필, 반드시 지킬 설정과 이번 화에 공개하지 않을 사실만 넣는다.
- 논리·인과 실패는 기존 `rewrite_draft`로 고친다.
- 줄거리는 통과했지만 문장과 문체만 약하면 별도의 `line_polish` 단계가 문제 문단만 보정한다. 새 사건·설정·대사를 추가하지 못하게 서버가 장면 수와 사건 해시를 비교한다.
- 문체 보정 뒤 인과 검수를 다시 전부 돌리지 않고 변경 문단과 경계 문단만 확인한다.

### 단계 F. 편집 관문

기존 점수에 다음 네 항목을 추가한다.

| 항목 | 기본 기준 | 판단 대상 |
| --- | ---: | --- |
| 문체 적합도 | 90 | 확정 문체 프로필의 리듬·어휘·유머·묘사 원칙을 지키는가 |
| 대화 인물성 | 86 | 이름을 가려도 목적·말의 정보 순서·태도로 인물이 구분되는가 |
| 어조 일관성 | 88 | 가벼움·웅장함·긴장감이 장면 목적에 따라 움직이며 임의로 흔들리지 않는가 |
| 문장 리듬 | 88 | 같은 길이·어미·강조가 반복되지 않고 행동과 감정의 호흡이 맞는가 |

`sceneExpression` 비평은 문장·문체 전문 비평으로 좁힌다. 최종 편집자는 점수만 평균내지 않고 다음을 별도로 판단한다.

- 장르를 제거하면 남는 인간적 욕망과 관계가 있는가
- 설정 설명을 제거해도 현재 회차에 성취·실패·발견·교감 중 하나가 남는가
- 주인공의 선택이 없었다면 같은 결과가 나왔을 것인가
- 웃음이나 웅장함이 형용사가 아니라 사건과 인물 반응에서 발생하는가
- 의무 없이 바로 다음 화를 읽고 싶은가

## 입력·비용·시간 개선

- 여섯 비평 역할마다 필요한 설정만 담은 역할별 압축 패킷을 만든다. 인물 비평에는 인물·관계·원고, 세계 인과에는 세계 규칙·원고, 문체 비평에는 문체 프로필·원고를 우선 제공한다.
- 공통 원고와 설정 해시는 유지해 잘못된 회차를 평가하지 않도록 한다.
- 독립 비평은 전역 동시 실행 1 정책을 바로 해제하지 않는다. 먼저 압축 패킷으로 호출 시간을 줄인 뒤, 운영 안정성이 검증되면 같은 비평 묶음 안에서 최대 3개만 병렬화한다.
- 기존 모델 정책은 유지한다: TERRA 초고, LUNA 비평·선정, 두 번째 구조 재작성부터 SOL. 새 문체 오디션은 TERRA 생성 후 LUNA 판정으로 시작한다.
- 비용 비교는 한 작품의 총 입력·출력 토큰, 재작성 횟수, 3편 승격까지 걸린 실제 시간을 함께 본다. 한 호출 가격만으로 모델을 판단하지 않는다.

- 장르 계열과 문체 프로필을 서버 상수로 정의하고 요청값을 화이트리스트 검증한다.
- 랜덤은 일정 등록 시 한 번만 해소하고 요청값과 확정값을 함께 저장한다.
- 설정집의 잠긴 문체 계약, 회차의 프로필 ID와 해시를 검증한다.
- 기존 일정에 값이 없으면 기존 장르와 생성된 `voiceProfile`을 유지한다. 소급 변경하지 않는다.
- 완료 기준: 브라우저를 우회한 잘못된 값이 거부되고, 재개·재시도·다음 화에서도 같은 확정값이 유지된다.

### 3단계. 장르별 기획·문체 오디션

- `genreExperiencePlan`과 문체 오디션 작업을 추가한다.
- 네 장르 계열별 후보 생성·선정 기준을 적용하고 서로 다른 계열의 약속이 섞이지 않게 검증한다.
- 오디션 실패는 문체만 한 번 보정하고 작품 기획을 무한 재생성하지 않는다.
- 완료 기준: 네 비공개 샘플이 장르 이름 없이도 서로 다른 보상 구조로 구분되고, 확정 문체와 샘플 판정이 감사 기록에 남는다.

### 4단계. 회차 재미·인과·문체 집필 계약

- 회차 카드에 장르 보상, 인물 매력 순간, 인과 사슬, 온도 변화, 대화 목적, 획득한 진전을 추가한다.
- 압축 `writingBrief`를 도입하고 전체 설정 데이터와 역할을 분리한다.
- 문체 전용 `line_polish`는 논리 재작성과 분리한다.
- 완료 기준: 재작성 뒤 사건 순서와 설정이 임의 변경되지 않고, 변경 문단·이유·전후 점수가 추적된다.

### 5단계. 검수 점수와 3편 파일럿 승격 강화

- 문체 적합도, 대화 인물성, 어조 일관성, 문장 리듬을 추가한다.
- 세 편 모두 확정 장르 보상을 제공하고 문체 적합도 90 이상이어야 자동 승격한다.
- 세 편에서 같은 웃음 방식, 같은 결말 질문, 같은 사건 해결법이 반복되면 운영자 확인으로 보낸다.
- 완료 기준: 높은 총점이 문체나 인과의 개별 실패를 덮지 못하고, 보류 화면에서 부족한 장면과 해결 버튼이 분명하다.

### 6단계. 비공개 비교 운영과 점진 배포

- 네 장르 계열마다 프롤로그+본편 1·2화 한 묶음을 비공개로 만든다.
- 기존 방식과 새 방식은 제목을 가린 채 동일 편집 기준으로 비교한다.
- 자동 지표로 상위 작품을 고르고 운영자에게는 상위 1~2개만 우선 제시한다.
- 한 번에 전체 자동연재를 전환하지 않고 새 일정 일부에만 적용한 뒤 실패율·시간·토큰·승격률을 확인한다.
- 완료 기준: 계약 오류 0건, 세 편 인과 평균 92 이상, 문체 적합도 평균 90 이상, 장르 약속 평균 90 이상, 세 편 모두 `wouldReadNext=true`, 평균 재작성 1회 이하를 만족한다.

### 7단계. 비용 최적화와 운영 기본값 확정

- 역할별 압축 패킷의 품질이 유지되면 같은 비평 묶음에 한해 최대 동시 실행 3을 검토한다.
- 장르 계열별 승격률과 운영자 예외 승격률을 보고 랜덤 가중치를 조정한다.
- 성능이 기준선보다 나빠진 프리셋은 기본 풀에서 내리고 테스트 전용으로 돌린다.
- 완료 기준: 품질 기준을 유지하면서 3편 파일럿의 총 시간과 입력 토큰을 기준선 대비 각각 25% 이상 줄인다.

## 테스트 계획

### 정적·단위 테스트

- 네 장르 계열이 유효한 기존 장르·세부장르 조합으로만 해소된다.
- 랜덤 결과가 일정 생성 뒤 바뀌지 않는다.
- 문체 프리셋의 잠긴 필드가 설정집·회차·재작성에서 변조되면 서버가 거부한다.
- 구형 일정과 진행 중 작품에는 새 필드가 없어도 기존 방식으로 이어진다.
- 문체 오디션과 `line_polish`가 사건, 인물 지식, 복선 상태를 바꾸지 않는다.

### UI 테스트

- 390px 모바일과 1440px 데스크톱에서 장르 계열·문체 선택과 도움말이 겹치지 않는다.
- 기본값은 장편 판타지 추천 랜덤과 가볍고 유쾌한 문체다.
- 수동 장르 변경, 설정 불러오기, 초안 복원, 새 설정이 서버 전송값과 일치한다.
- 일정 카드와 작업 상세에서 요청한 계열, 실제 확정 장르, 확정 문체를 한국어로 확인할 수 있다.

### 생성 품질 테스트

- 네 계열마다 자체 인물과 사건을 가진 비공개 3편 파일럿을 생성한다.
- 장르 이름과 프리셋 이름을 가린 블라인드 편집에서 장르 보상과 문체를 올바르게 구분하는지 본다.
- 인과 사슬의 원인·선택·결과가 원고에 실제로 나타나는지 기계 근거와 편집 근거를 함께 저장한다.
- 작품명·작가명·고유 용어가 워커 입력, 출력과 감사 로그에 포함되지 않는지 검사한다.

### 운영 테스트

- 중지, 재개, 재시도, 일정 불러오기, 다음 화 제작 뒤에도 장르·문체 해시가 유지된다.
- 문체 검수 실패가 `시스템 중단`으로 보이지 않고 `문체 보완 필요`로 표시된다.
- 실패 사유와 재개 버튼은 해당 단계에 맞으며 다른 대기 작품과 일정 주기를 바꾸지 않는다.
- 단계별 입력·출력 토큰, 실제 시간, 재작성 횟수와 모델을 비교 리포트에 남긴다.

## 배포 원칙

- 기존 작품과 기존 일정은 자동 변경하지 않는다.
- 새 기본값은 신규 설정에서만 적용한다.
- 특정 작품과 비슷하다는 점수는 만들지 않는다. 평가 대상은 장르 약속, 문체 계약, 인물 선택, 관계 변화, 인과, 회차 보상이다.
- 한 프리셋이 높은 점수를 받더라도 네 장르 계열의 표면 설정과 사건 순서가 비슷하면 배포하지 않는다.
- 품질 점수와 실제 다음 화 독서 의향이 충돌하면 자동 공개보다 비공개 보류를 선택한다.
- 운영 화면에는 기술 필드 대신 `장르 재미`, `문체`, `인과`, `다음 화 의향`과 부족한 장면을 우선 표시한다.

## 최종 완료 조건

1. 운영자는 새 설정에서 장르 계열 하나와 문체 하나만 골라도 안정적인 장편 판타지 작업을 시작할 수 있다.
2. 아무것도 바꾸지 않으면 네 장편 판타지 계열 중 하나와 가볍고 유쾌한 문체가 적용된다.
3. 문체 랜덤을 선택해도 한 작품 안에서는 프롤로그부터 후속 회차까지 같은 목소리를 유지한다.
4. 3편 파일럿이 장르 보상, 인물 애착, 관계 변화, 인과, 문체 기준을 모두 통과해야 자동 승격한다.
5. 기존 작품, 일정과 공개 원고는 소급 변경되지 않는다.
6. 참고 작품의 이름·작가·원문·고유 설정이 생성 프롬프트에 들어가지 않는다.
7. 비교 리포트에서 새 방식이 기준선보다 품질이 높고 계약 오류·시간·토큰이 운영 가능한 범위임을 확인한다.
